# MASTER PROMPT — СОЗДАЙ ГОТОВУЮ ИГРУ «ПОСЛЕДНИЙ СИГНАЛ»

Ты — команда сценаристов, художников, геймдизайнеров и frontend-разработчиков. Прочитай `docs/СЦЕНАРИЙ_И_БИБЛИЯ.md`, используй все ресурсы архива, при необходимости для разнообразия создавай дополнительно свои и создай законченный продукт — браузерную визуальную новеллу, а не макет.

## Цель
70–100 минут первого прохождения, 6 полноценных глав, русский язык, кинематографичная подача в духе интерактивных романтических новелл уровня «Клуба Романтики» без копирования их материалов. Напиши минимум 9 000 слов сценария (или работай последовательно по главам, сохраняя промежуточные файлы, если ограничен контекстом). Каждая глава должна содержать полноценные диалоги, сцены, выборы, последствия и клиффхэнгер.

## Визуальные ресурсы
Используй SVG-фоны из `assets/backgrounds/`, временные портреты из `assets/characters/`, музыку из `assets/audio/`. Если у тебя есть встроенная генерация изображений, создай согласованные оригинальные спрайты персонажей (эмоции/позы), минимум 12 дополнительных фонов и 8 CG-сцен. Сохраняй внешность Виты: длинные чёрные волнистые волосы, зелёные глаза, узнаваемые черты лица по приложенному референсу. Константин — художественный образ; не выдумывай факты о внешности реального пользователя. Если генерация недоступна, используй имеющиеся SVG аккуратно и не оставляй пустых слотов.

## Игровые механики
- Главное меню, новая игра, продолжить, выбор глав.
- Диалоговый интерфейс, имена говорящих, история реплик.
- Минимум 35 осмысленных выборов.
- Характеристики closeness, trust, resolve, resources.
- Отложенные последствия, романтические сцены по близости.
- 3 базовых финала и персональные эпилоги.
- Автосохранение и ручное сохранение через localStorage.
- Быстрый пропуск прочитанного текста.
- Галерея открытых CG, профили персонажей.
- Регулировка музыки и звуковых эффектов.
- Музыка плавно меняется по сценам, используй WAV из assets/audio.
- Все кнопки реально работают.

## GitHub Pages — обязательно
Игра должна публиковаться через GitHub Pages без backend:
1. Все пути к ресурсам относительные, не начинаются с `/`.
2. Статические HTML/CSS/JS, без секретных API-ключей.
3. localStorage для прогресса.
4. Добавь `.nojekyll`, README и точную инструкцию.
5. Деплой: GitHub repository → загрузить файлы в корень → Settings → Pages → Deploy from a branch → main → /(root) → Save.
6. Проверь корректность путей и мобильную адаптацию.

## Архитектура
Сохрани модульную структуру: `index.html`, `styles.css`, `src/engine.js`, `src/story.js`, `src/state.js`, `assets/`, `docs/`. Можно изменить архитектуру, если это улучшает качество, но проект должен оставаться статическим и GitHub Pages-ready.

## Качество
Никаких фиктивных кнопок, заглушек под видом готовых функций, неработающих выборов или недостижимых финалов. Проверить все ветки, сохранение после перезагрузки, смену музыки, мобильный экран. Не заявляй, что создал изображение или музыку, если файла нет.

## Финальная сдача
Предоставь готовый архив/репозиторий с исходниками, сценарием, ресурсами, инструкцией запуска и GitHub Pages. В финальном отчёте перечисли реализованные функции и оставшиеся ограничения. Не останавливайся на плане — реализуй продукт.
